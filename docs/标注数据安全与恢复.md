# 标注数据安全与恢复

本文针对标注文件丢失、写入失败和误操作，不代表对所有网络或系统安全问题完成了渗透测试。

## 日常使用

1. 将 JSON 作为包含类别、几何和属性的标注源文件。YOLO、VOC XML 和 CurveLanes 导出不能完整保存任意属性。
2. 编辑完成后等待自动保存，并定期按 **Ctrl+S**。自动保存会合并短时间内的编辑，延迟约 0.6 秒；未完成的多边形、强制结束前尚未保存的更改或断电时的最后操作可能丢失。
3. 定期把整个图片项目、标注输出目录及类别和属性配置复制到另一块磁盘或可信的备份位置。本程序的本地备份与原文件通常在同一磁盘，不能抵御磁盘损坏。
4. 不要让多个 JotMark 实例或其他软件同时编辑同一项目。标注文件与属性配置在写入前会检查文件内容是否变化，但没有提供跨进程事务锁，无法消除并发写入的所有竞态；`classes.txt` 和 `class_colors.json` 尚不具备同等的外部修改检测。
5. 同一图片目录中不要同时使用 `road.jpg`、`road.png` 等同名不同后缀图片：它们会映射到同一个 `road.json`。发现此情况时程序会阻止保存，请先备份后重命名其中一张图片。

## 保存失败时

当底部显示 **保存失败：未保存** 时，画布中的修改仍在内存。保存失败的详情可在提示中查看；切换图片、目录、格式及关闭窗口会被阻止，避免直接丢弃待保存的内容。

1. 不要立刻强制结束程序。检查磁盘空间、目录权限，以及是否有其他软件修改了标注文件。
2. 点击底部 **另存恢复**，选择一个不存在的新 JSON 文件名，必要时选择其他磁盘。程序不会覆盖同名已有文件。
3. 如果原标注读取不完整，恢复文件只包含当前画布能看到的内容，不能保证是原标注的完整副本。原文件被保护而不会自动覆盖，请另外保留原文件供检查。
4. 成功另存后，如原位置仍无法保存，可确认关闭；如果继续编辑，或恢复文件在关闭前被改动、删除，需要重新保存恢复文件。
5. 恢复时在**新目录**放入对应图片，将恢复 JSON 改成与图片主文件名相同的名称，例如图片 `road.png` 对应 `road.json`。同时复制需要的 `classes.txt`、`class_colors.json` 和 `class_attributes.json`，打开新目录后检查类别、数量、几何和属性。

如果软件已完全无响应，以上另存操作可能无法执行。先复制磁盘上已有的标注文件及配置，再考虑手动关闭；没有写入磁盘的内存内容不能保证恢复。

## 备份和回收站位置

- 每次覆盖已有标注前，前一版位于标注输出目录 `.jotmark_backups/annotation-history/`。例如 `road.json.previous` 对应 `road.json`。此位置只保留**一个最近的先前版本**，再次保存后会更新它。恢复时先复制到新项目目录，再去掉 `.previous`。
- 删除最后一个标注后，旧文件移动到标注输出目录 `.jotmark_trash/annotations/`，文件名包含随机后缀。可复制到新目录并改回原文件名，不要直接覆盖尚未备份的现有文件。
- 类别重命名、删除以及在属性管理中更改属性树之前，会尝试在项目的 `.jotmark_backups/category-change-*/` 创建快照。`project` 和（与项目目录不同时）`annotations` 子目录分别保存对应目录下的 JSON、XML 和 TXT 文件。备份失败时操作会取消。
- 属性文件导入时另有 `.jotmark_backups/attribute-schema-import-*/` 备份。类别和属性配置的上一版也保存在 `annotation-history`。

类别或属性的批量修改不是跨文件原子事务。若提示部分文件失败，不要继续处理；先保存当前画布到独立恢复文件，再结合快照人工检查和恢复。不要在其他程序仍写入同一目录时覆盖恢复。

属性配置读取后保存时会保留配置和属性节点中的未知字段；导入其他属性配置时以导入文件的定义和附加字段为准。确认旧版配置已经备份后再导入或更改属性。

## 模型辅助标注

批量预测前会先处理当前画布待保存内容。已有 JSON 追加时保留原有标注、属性和自定义字段；预测期间检测到目标文件被其他程序修改时会停止。覆盖模式会备份上一版，清空的标注会移入回收站。

为防止旧逻辑把已有几何错误转换成矩形，向已有 YOLO 或 XML 文件批量追加暂时被禁止。请改用 JSON，或在确认备份后明确选择覆盖。批量任务中途失败或取消时，已经处理完成的图片不会自动回滚；应结合输出目录的备份核对。

程序读取不完整或不支持的 JSON、YOLO、XML、CurveLanes 标注时会保护原文件，避免后续自动保存覆盖。JSON 中的 `imagePath` 若指向其他图片，也会被保护；如果图片确实已改名，请先备份，再在副本中核对并修正。请查看错误详情、保留原始副本，再检查格式或使用适配工具转换。
